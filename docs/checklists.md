# Task checklists

Each card has one optional checklist. Existing cards default to an empty list;
no backfill is required. The detail modal supports adding, renaming, completing,
reopening, and removing items. Changes save immediately, independently of the
card detail form's Save/Cancel actions. Cards display completed/total counts.
Completing the checklist does not automatically change the card status.

## Mutation contract

Use `PATCH /api/v1/boards/:boardId/cards/:cardId` or Socket.IO `card:update` with
an `updates` payload containing only `checklistOperation` (REST uses that payload
as its request body):

```json
{ "checklistOperation": { "action": "add", "title": "Write API tests" } }
```

`update` accepts `itemId` and `title`, `completed`, or both. `remove` accepts
`itemId`. IDs are generated by MongoDB. Titles must be 1-300 characters after
trimming; each card supports up to 100 items. Replacing the entire checklist is
rejected to prevent stale clients from overwriting teammates' changes.

Owners, admins, and members use the existing card permission checks. The shared
mutation service delegates checklist writes to `checklistService.js`, which uses
atomic item operations scoped to both project and card. Concurrent edits to
different items are preserved; edits to the same field use last-write-wins.
Responses contain the saved card. Socket mutations broadcast `card:updated` to
other room members; REST mutations broadcast to all connected room members.
Both paths record `card.updated` activity.

Checklist items are embedded in the card and disappear when the card is deleted.
These are lightweight to-dos, not independent subtasks with assignees or dates.

## Review checks

- Add items, tick/untick, rename, and remove; reopen the card and reload the page.
- Open a card with two accounts and edit different items simultaneously.
- Confirm card progress updates in both sessions without resetting form drafts.
- Check empty checklists, long titles, mobile layout, and dark mode.
- Verify errors retain the draft and allow retry.
